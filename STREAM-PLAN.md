# SkyGraph — Опорный план длинных стримов

> Документ-опора для последующих автономных циклов работы.
> Версия: v0 (черновик, согласован устно).
> Все стримы запускаются командой "стартуй стрим N" — без дополнительного обсуждения.

---

## ⚠ ГЛАВНОЕ ПРАВИЛО (ВЫШЕ ВСЕХ ОСТАЛЬНЫХ)

**В течение стрима НЕ задавать пользователю никаких вопросов. Никогда. Ни при каких условиях.**

Это правило имеет приоритет над любыми другими дефолтами, инструкциями, политиками безопасности (кроме явно деструктивных операций — git push --force, rm корневых директорий и подобного).

### Почему это критично

При долгом стриме контекст переписки переполняется и старые сообщения обрезаются автоматически. Если правило живёт только в чате — оно потеряется через 30–60 минут работы, и агент начнёт «вежливо уточнять у пользователя», разрушая стрим.

Поэтому правило живёт **здесь, в файле репозитория**. Читай этот документ в начале каждого стрима и при любых сомнениях.

### Что делать вместо вопроса пользователю

Любая ситуация, в которой возникает желание спросить пользователя, разрешается так:

1. **Принять решение самостоятельно** в сторону минимального скоупа.
2. **Записать** принятое решение и причину в `CYCLE-LOG.md` (раздел "Решения по развилкам").
3. **Продолжить работу**.

Если решение оказалось плохим — пользователь увидит его в логе после стрима и скажет переделать. Это нормально и дешевле, чем ломать стрим вопросом.

### Конкретные триггеры, при которых тянет спросить — и что делать

| Ситуация | Правильное действие |
|----------|---------------------|
| Не уверен в имени файла / поля / API | Выбирай как в соседних модулях, фиксируй в логе |
| Не понимаю что хотел пользователь в скоупе | Бери минимальное толкование, остальное в `TODO-cycle.md` |
| Сломался чужой тест | Откатить свою правку в этом месте, отметить в логе, идти дальше |
| Упёрся в архитектурный выбор | Минимальный путь, фиксируй альтернативы в логе |
| Кажется, нужны новые зависимости | Не ставить. Зафиксировать в `TODO-cycle.md` как требование к будущему стриму |
| Кажется, нужно править публичный API | Не править. Зафиксировать в `TODO-cycle.md` |
| 3 неудачные попытки решить проблему | Зафиксировать в логе, пропустить, идти дальше |
| Близко к концу контекста | Сохранить полный отчёт в `CYCLE-LOG.md` и закончить turn — НЕ спрашивать "продолжать?" |

**Запрещённые формулировки в течение стрима:**
- "Хочешь ли ты, чтобы..."
- "Уточни, пожалуйста..."
- "Подскажи..."
- "Какой вариант выбрать..."
- "Продолжать?"
- Любые AskQuestion / SwitchMode tool calls.

## Принципы работы в стриме

- Один стрим = одна крупная фаза, выполняется до критерия стопа без вопросов пользователю.
- На любой развилке — **минимальный скоуп**, отложенное пишется в `TODO-cycle.md`.
- Лог хода работ — `CYCLE-LOG.md`. После стрима пользователь сверяет.
- Все решения по неоднозначностям — туда же, в лог.
- Если упёрся в проблему 3+ раз — фиксируй в логе и пропускай.
- **При старте любого стрима первым делом читай раздел "ГЛАВНОЕ ПРАВИЛО" этого файла.**

## Глобальные полномочия (дефолт)

- Создавать / править / удалять файлы в скоупе текущей фазы.
- Запускать `pnpm test`, `pnpm lint`, `pnpm build`, `pnpm format`.
- Запускать sub-агентов через Task для изолированных кусков работы.
- Читать любые файлы репозитория.

## Глобальные запреты (дефолт)

- НЕ делать `git push` (никогда, ни в какой стрим).
- НЕ делать `git commit --amend`, `git rebase`, `git merge`, `git reset --hard` (никогда).
- НЕ создавать новые ветки (репозиторий — личное пространство одного владельца).
- НЕ менять публичный API существующих движков (`form`, `table`, `tree`, `virtual`) без отдельного скоупа.
- НЕ трогать стилевые токены `--sg-*` и файлы в `packages/react/styles/tokens.css` / `themes/` без отдельного скоупа.
- НЕ удалять чужие неотслеживаемые файлы.
- НЕ ставить новые зависимости без явного разрешения в стриме.

## Политика коммитов в стриме

Коммиты разрешены и обязательны — это даёт точки отката и историю по фазам, чтобы пользователь мог легко отследить изменения после стрима.

**Куда коммитить:**
- В текущую ветку. Никаких новых веток не создавать.

**Формат commit message:**
```
cycle(N): <короткое описание фазы>
```
где `N` — номер стрима из этого документа.

Примеры:
```
cycle(1): create AUDIT.md skeleton with section headers
cycle(5): add Node, Edge, Outline types in graph engine
cycle(5): implement basic operations (addNode, removeNode, moveNode)
cycle(2): set up i18n infrastructure with react-i18next
```

**Когда коммитить:**
- После каждой логически законченной фазы.
- Когда `pnpm lint` чистый и `pnpm test` зелёный (если в скоупе фазы есть тестируемая логика).
- Перед сменой логического раздела работы.
- Перед запуском sub-агента для изолированной задачи (на случай отката).

**Когда НЕ коммитить:**
- При красных тестах в файлах, которые относятся к скоупу стрима.
- При ошибках сборки или линта в изменённых файлах.
- Если в рабочей копии есть файлы вне скоупа стрима — добавлять их в коммит нельзя, использовать `git add <конкретные пути>`.

**При падении pre-commit hook:**
- Прочитать вывод hook.
- Исправить проблему.
- Сделать **новый коммит** (не `--amend`).
- Зафиксировать инцидент в `CYCLE-LOG.md`.

**Что коммитить в одном коммите:**
- Только файлы, относящиеся к одной фазе одного стрима.
- Обновления `CYCLE-LOG.md` и `TODO-cycle.md` — отдельным коммитом в конце фазы или вместе с её последним коммитом, на усмотрение.

## Дефолты для развилок

- Архитектурный выбор → следовать стилю существующих движков.
- Именование → как в соседних модулях.
- Спорная фича → минимальный скоуп, остальное в `TODO-cycle.md`.
- Падает свой тест → исправить.
- Падает чужой тест → откатить **свою** правку, отметить в логе, идти дальше.
- Конфликт типов → сохранять обратную совместимость публичного API.
- Язык кода и комментариев → английский (по сложившемуся стилю репозитория).
- Язык логов и отчётов (`CYCLE-LOG.md`, `AUDIT.md`) → русский.

## Очередь стримов

### Стрим 1 — Аудит всей системы

**Цель:** независимый отчёт о состоянии репозитория.
**Артефакт:** `AUDIT.md` в корне.
**НЕ ВХОДИТ:** правки кода. Только чтение и отчёт.

**Что аудируется:**
- Архитектурные нарушения границ (runtime → engines, engines → engines, ui → core).
- Dead code, дубли, неконсистентное именование.
- Расхождения `README.md` / `ARCHITECTURE.md` с фактическим состоянием.
- Состояние тестов и покрытие.
- Состояние стилевого контракта (`docs/styling-contract.md`, `docs/styling-recipes.md`).
- Состояние `examples/demo` и `examples/showcases`.
- Устаревшие зависимости и инфраструктурные вопросы.

**Критерий стопа:** все секции отчёта заполнены, перечислены приоритеты исправлений.

---

### Стрим 2 — Локализация демо-проекта (i18n)

**Цель:** весь `examples/demo/` и `examples/showcases/` переведены на i18n с поддержкой русского и английского.
**Артефакт:**
- инфраструктура i18n (выбор: `react-i18next` или минималистичное собственное решение через `ConfigProvider.locale` — решается на старте стрима);
- переключатель языка в шапке демо;
- все строки вынесены в локали (`locales/ru.ts`, `locales/en.ts` или эквивалент).

**НЕ ВХОДИТ:** локализация самой библиотеки `@skygraph/react` (там уже есть `locales/en_US.ts` и `ru_RU.ts`).

**Критерий стопа:** все демо-страницы открываются на ru/en, нет хардкодных строк, lint чистый, тесты не сломаны.

---

### Стрим 3 — a11y-перепроверка

**Цель:** ревизия доступности по всем компонентам.
**Артефакт:** исправления + `A11Y-CHECKLIST.md` с пометками "проверено / исправлено / отложено".

**Чек по каждому компоненту:**
- ARIA-роли и атрибуты;
- keyboard-навигация (Tab, стрелки, Esc, Enter);
- focus trap (для модалок, drawers, popconfirm);
- видимый focus ring;
- screen-reader тексты (aria-label, aria-describedby, sr-only).

**Критерий стопа:** чек-лист закрыт по всем компонентам в `packages/react/src/components/`, существующие a11y-тесты зелёные.

---

### Стрим 4 — Рефакторинг examples/showcases

**Цель:** декомпозиция плохо организованных демо-приложений.
**Контекст:** `AdminApp.tsx` — 562 строки одним файлом. Подобные проблемы в других showcases.

**Что делаем:**
- бить большие файлы на компоненты по фичам;
- отделять данные/логику от рендера;
- единый шаблон страницы шоукейса;
- консистентная структура папок (`pages/`, `widgets/`, `data/`).

**Критерий стопа:** ни один файл в `examples/showcases/src/` не превышает порог в 250 строк, все шоукейсы открываются и работают, lint чистый.

---

### Стрим 5 — GraphEngine (диаграммный движок)

**Цель:** новый движок графов как четвёртый в линейке `form/table/tree/virtual`.

**Скоуп:**
- модель: `Node`, `Edge`, `parentId`-иерархия, `outline` (rect / ellipse / polygon / path-flatten), `anchorPolicy`, `transform`, `bounds`, `data`;
- операции: `addNode`, `removeNode`, `moveNode`, `addEdge`, `removeEdge`, `setParent` (вложенность);
- генератор якорей (1..k на ребро или равномерно по периметру с нормированным параметром `s ∈ [0..1]`);
- инкрементальный пересчёт через `geomRevision` + `edgesByNode`;
- прямые рёбра между якорями (без orthogonal-роутера в этом стриме);
- юнит-тесты на vitest;
- минимальный React-компонент `<Diagram>` с DOM-узлами + SVG-overlay для линий;
- демо-страница в `examples/demo/src/demos/diagram/Basic.demo.tsx`.

**НЕ ВХОДИТ:** orthogonal-роутер (избегание препятствий), undo/redo, snap-to-grid, drag-and-drop из палитры, повороты узлов.

**Критерий стопа:** тесты зелёные, простой пример с 3 узлами и 2 связями работает в demo, lint чистый.

---

### Стрим 6 — Усиление TableEngine

**Цель:** конкретный список pro-фич (точный список фиксируется в момент запуска стрима).

**Кандидаты в скоуп (выбрать на старте):**
- pinning колонок (left / right);
- column resize / reorder с persist в state;
- виртуализация с динамической высотой строк;
- группировка строк + агрегации;
- экспорт CSV;
- расширенные фильтры (between, in, custom predicate).

**Критерий стопа:** выбранные фичи реализованы, тесты зелёные, демо обновлено, lint чистый.

---

### Стрим 7 — Графики (низкий приоритет, опционально)

**Цель:** каталожные базовые диаграммы как UI-компоненты.
**Принцип:** не движок состояния, просто рендер. SVG.

**Скоуп:**
- `<LineChart>`, `<BarChart>`, `<AreaChart>`, `<PieChart>`;
- общий контракт данных (серии + категории);
- легенда, оси, tooltip;
- темизация через `--sg-chart-*` токены.

**Критерий стопа:** 4 типа графиков работают на тестовых данных, демо-страницы созданы, lint чистый.

## Стримы из «не дозакрытых мест» (запускаются после Стрима 7)

### Стрим 8 — Стандартизация шаблона демо

**Цель:** единая структура каждого компонента в `examples/demo/`: Basic / Advanced / Edge cases / Tokens / API.
**Артефакт:** обновлённая структура `examples/demo/src/demos/`, generator-скрипт для нового компонента (опционально).
**Контекст:** часть может закрыться Стримом 4, после Аудита уточним точный скоуп.

### Стрим 9 — Обновление документации

**Цель:** `ARCHITECTURE.md`, `docs/styling-contract.md`, `docs/styling-recipes.md`, `README.md` приведены в соответствие с реальным состоянием после Аудита и предыдущих стримов.
**Критерий стопа:** все расхождения, найденные Аудитом, устранены.

### Стрим 10 — Performance-бенчмарки

**Цель:** замеры Form / Table / Tree / Graph на больших объёмах данных (1k, 10k, 100k записей).
**Артефакт:** `BENCH.md` с результатами, скрипты бенчмарков в `packages/*/src/__tests__/benchmark.test.ts` (часть уже есть).

### Стрим 11 — Дашборды / конструктор отчётов

**Цель:** компонент `<Dashboard>` с drag-layout сеткой и виджетами (привязка к данным остаётся за приложением).
**Контекст:** обсуждалось как «попадает в идею SkyGraph» (есть состояние layout, виджетов, фильтров).

### Стрим 12 — Gantt / Timeline / Resource Calendar

**Цель:** новый сложный компонент уровня complex (с собственным движком — задачи, зависимости, конфликты ресурсов).
**Контекст:** обсуждалось, не записано в основную очередь.

### Стрим 13 — Schema Forms — визуальный редактор

**Цель:** визуальный редактор JSON Schema (FormEngine + GraphEngine вместе как доказательство связности движков).
**Зависит:** Стрим 5 должен быть закрыт.

### Стрим 14 — Print / PDF пайплайн

**Цель:** инфраструктура печати таблиц / форм / диаграмм с сохранением форматирования.
**Статус:** обсуждалось, явно отложено.

### Стрим 15 — Релизный стрим 0.2

**Цель:** собрать всё готовое, обновить `CHANGELOG.md`, выставить версии в `package.json`.
**НЕ ВХОДИТ:** публикация в npm — только подготовка релиза локально.
